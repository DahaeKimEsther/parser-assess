# 커밋 메시지 규칙

커밋은 사용자가 요청할 때만 수행한다. 메시지는 한국어로 쓴다.

## 제목

- 형식: `* <이모지>Type: 변경 내용 설명`
- 설명은 한국어로, 무엇을 왜 바꿨는지 한 줄로 작성
- 예시: `* ⭐Feature: 빈 문서에 텍스트만 있는 경우 parser를 사용하지 않는 로직 추가`

### 사용하는 Type

- ⭐Feature: 새로운 기능 추가
- 🐛Fix: 버그 수정
- 🧹Chore: 빌드, 설정, 패키지, 불필요한 코드 정리 등 동작에 영향 없는 잡다한 작업
- ♻️Refactor: 기능 변화 없이 코드 구조만 개선
- 📝Docs: README 등 문서 추가·수정

### 작성 원칙

- 한 커밋에는 한 가지 목적만 담기
- 여러 성격이 섞이면 비중이 가장 큰 변경 기준으로 Type을 하나만 선택
- 위 다섯 가지 외의 Type은 사용하지 않기
