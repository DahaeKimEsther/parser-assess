## 결정과 이유

- **실험/벤치마크 지향을 버리고 문서처리 모듈로 재정의**: 처음에는 단계별(청킹·임베딩·검색·리랭킹·생성) 교체 가능한 실험 틀을 설계했지만, 규모가 크고 "벤치마크처럼 가고 있다"는 판단으로 폐기했다. 목표는 문서가 계속 추가되는 환경에서 유형별 처리와 처리 시간 단축이다.
- **저장소 이름은 바꾸지 않음**: `rag-ingest` 등 후보를 논의했지만, 이름 변경 대신 `src/rag_lab/parser/`에 구조를 두고 점진적으로 확장한다.
- **범위 축소**: 교체 가능 구조(인터페이스, 레지스트리, 설정)만 유지하고 인덱스 캐시, LLM 구현체, compare CLI는 뒤로 미뤘다.
- **한 문서의 실패가 배치를 멈추지 않게 격리**하고, 처리 시간은 `.cache/parser/metrics.jsonl`에 기록한다.
- **평가 구조는 `assess/X/`가 `rag_lab/X/`를 평가**: 평가 대상이 청킹·임베딩·검색으로 늘어날 것이기 때문이다. 공통 폴더는 두 번째 평가 대상이 생길 때까지 만들지 않는다(미리 추상화 금지). `complexity.py`는 운영 라우터도 쓰므로 `parser/`에 두고, `assess`가 가져다 쓴다(역방향 의존 금지).
- **LiteParse는 OCR을 끄고 선택 의존성으로 분리**: 미설치 시 안내와 종료 코드 2를 반환한다. 복잡도 점수 가중치는 잠정값이다.
- **인수인계는 git에서 추적되는 `TODO.md`로**: `.claude/plans/`는 git 제외라 worktree에서 읽을 수 없기 때문이다.
- **범용 스킬은 저장소 밖(전역)에 둠**: 저장소에는 이 저장소만의 지식이 든 스킬만 둔다. 용량이 크고 RAG와 무관하며, 공개 저장소에 올릴 이유가 없다.
