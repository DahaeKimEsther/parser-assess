# Decisions

사용자가 확정한 결정만 적는다. 계획이나 설계를 세우기 전에 먼저 읽고, 여기서 접은 항목은 다시 꺼내지 않는다.

## 사용 규칙

- 새 결정은 사용자가 확정한 뒤에만 적는다. 제안이나 추측은 적지 않는다.
- 바뀐 결정은 지우지 않고 `폐기됨`으로 표시하고, 대체한 결정을 가리킨다.
- 항목이 20개쯤 넘으면 `docs/decisions/`로 나눈다.

## 항목 형식

```
### YYYY-MM-DD 결정 한 줄
- **결정**: 무엇으로 정했는가
- **이유**: 왜 그렇게 정했는가
- **하지 않기로 한 것**: 접은 대안, 지금은 신경 쓰지 않기로 한 것
```

## 목록

### 2026-11-24 저장소를 파서 평가 전용(parser-assess)으로 좁힌다
- **결정**: 저장소 이름은 `parser-assess`, 패키지명은 `parser_assess`로 한다. 처리 파이프라인을 제거하고 평가 로직(복잡도 점수, LiteParse 엔진, `complexity` 명령)만 남긴다. 패키지명이 이미 평가를 뜻하므로 `assess/` 하위 폴더는 두지 않는다.
- **이유**: 목표가 "사내 문서 RAG 전체"에서 "파서가 벤치마크에서 어느 문서까지 쓸 만한지 판단"으로 바뀌었다. 이전에 `complexity.py`를 `parser/`에 둔 이유(라우터 재사용)는 라우터가 사라져 해소됐다.
- **하지 않기로 한 것**: 문서 처리(`.md` 변환)·처리 시간 측정·라우팅, RAG 후속 단계(청킹·임베딩·검색) 확장. 이전 구현은 git 이력(`618f748` 이전 커밋)에서 되살릴 수 있다.
